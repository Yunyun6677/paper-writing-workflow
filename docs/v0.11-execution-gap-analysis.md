# v0.11 Execution Gap Analysis

Date: 2026-09-14
Audited baseline: repository commit `52b5094`
Release baseline: v0.10.0; the existing v0.11 headings were premature development notes, not a production-certified release.

## Audit method

This audit reads implementation and tests rather than accepting README claims. It inspected the runtime, planner, stores, tools, guardrails, memory, evaluation, tracing, provider boundary, CLI, all JSON schemas, the five specialist `SKILL.md` files, configuration files, and runtime tests. The baseline command

```powershell
.venv-empirical/Scripts/python.exe -m unittest discover -s tests -p 'test*.py' -v
```

ran 21 tests successfully. These tests establish only the scopes stated below. They do not constitute a live-model, real-tool, semantic-science, or end-to-end certification.

## Capability levels

- **Documented**: described in prose or a manifest.
- **Implemented**: executable code exists for the stated path.
- **Tested**: an automated test executed the stated behavior with synthetic or controlled inputs.
- **Production-certified**: a maintained real integration has passed representative end-to-end tests, failure injection, security review, and release evidence. No v0.10 agent execution path meets this level.

## Executive finding

v0.10 is a useful persistent orchestration kernel, not yet an executing Research Agent System. The canonical loop can choose tasks, persist transitions, verify declared file hashes, retry, replan, pause, resume, and recover. For every `agent` or `verifier` task, however, `ResearchRuntime.run()` writes an assignment packet, changes the task to `waiting-agent`, and returns. Only a separate caller invoking `observe_agent()` can restart progress. `ProviderAdapter` is not connected to the runtime, no active provider is configured, and no specialist is actually invoked.

The central v0.11 gap is therefore one connected execution path:

```text
ResearchRuntime
  -> AgentExecutor
  -> ModelAdapter
  -> context-limited Specialist
  -> real ToolRegistry adapters
  -> schema-valid proposal/observation
  -> independent evidence verification
  -> canonical state transition by ResearchRuntime only
```

## Which agents still require external `observe`?

All task nodes with `task_type` equal to `agent` or `verifier` do:

- Research Director framing (`frame`)
- Literature Agent (`literature`)
- Reviewer for literature (`literature-review`)
- Empirical Agent design (`empirical-design`)
- Reviewer for design (`design-review`)
- Empirical Agent execution (`analysis`)
- Reviewer for empirical outputs (`empirical-review`)
- Writing Agent (`writing`)
- Reviewer for manuscript (`manuscript-review`)
- every dynamically created literature, robustness, or manuscript-revision agent task

The runtime creates no model call. The CLI `observe` command accepts a JSON file supplied by an external actor. Artifact existence and hashes are checked after a PASS-like observation, but there is no proof that a specialist produced the content or that the content is scientifically valid.

## Which tools are only staged?

The catalog declares these staged integrations: Zotero, CNKI browser, OpenAlex/Crossref/Unpaywall, PDF parser, Python, Stata, R, LaTeX, and Git. The active default registry contains only:

- `schema_validate`
- `artifact_integrity`
- `research_firewall`
- `research_guardrails`

The repository has useful standalone scripts for empirical engines, acquisition, PDF extraction, Zotero and LaTeX-related workflows, but they are not yet registered through one execution contract with process isolation, receipts, idempotency and runtime routing. A standalone script succeeding in a prior workflow is not equivalent to a v0.11 Tool Adapter integration.

## Which guardrails trust fields instead of facts?

- Citation Guardrail trusts `verification_status=verified` and `entailment_status=passed`.
- Fulltext Guardrail trusts `fulltext_status=obtained` and `actually_read=true`.
- Causal Claim Guardrail trusts `identification_status=passed` or a supplied `qualified_language` flag.
- Specification Guardrail reads the supplied reason/approval fields but does not compare a proposed specification to a locked design artifact.
- Sensitive Data Guardrail checks declared sensitivity and side-effect fields; it does not enforce an execution sandbox or inspect the actual data flow.
- Numeric Guardrail is stronger because the tool adds file existence and SHA-256 checks, but it still does not prove that the displayed value, estimator, sample and model identifier occur in the referenced artifact.

## Which memory is only structure?

`empty_memory()` creates working, project, preference and evidence dictionaries inside canonical state. The project layer stores decisions/revision history, the evidence layer stores artifact references, and a recursive key denylist blocks obvious secrets/raw-data keys. Missing capabilities include durable entity identity, claim/evidence relationships, query/index support, provenance-aware updates, project-wide reuse, token-bounded retrieval, least-context enforcement, and content-level sensitive-data controls.

## Which evaluation is operational only?

`research_os/evaluation.py` reports task counts, completion rate, waits, errors, retries, artifacts, checkpoints and checkpoint integrity. `research_os/evals.py` computes useful domain metrics from pre-labelled fixtures, but it evaluates fixture declarations rather than live system behavior. There is no current measurement of live routing correctness, planning validity, semantic entailment, specification drift, end-to-end reproduction, duplicate external side effects, resume equivalence, model cost or real wall time.

## v0.11 implementation priority derived from the audit

1. Define the framework-neutral `ModelAdapter` contract and a runtime-owned `AgentExecutor`.
2. Connect a deterministic `MockModelAdapter`; prove that the runtime advances without external `observe`.
3. Add one real executable adapter (OpenAI Agents SDK or Codex CLI) behind the same contract.
4. Integrate Tier-1 tools with process-group termination, path/environment/network policy, receipts and idempotency.
5. Make Literature, Empirical, Writing and Reviewer roles executable with compiled least-context packets.
6. Replace status-field trust with deterministic and model-assisted EvidenceVerifier receipts.
7. Run synthetic/public E2E projects with failure injection through final audit and human-gate simulation.
8. Only after 1--7, add ScientificMemoryStore, ContextPacker, expanded evaluation, SQLite StateBackend, then Tier-2/Tier-3 tools.

## Release gate

The version must remain v0.10.x / v0.11-development until a real research question + ten public papers + public CSV + OLS project completes the specified end-to-end path, including verifier rejection and follow-up, process restart/resume, corrupted-checkpoint recovery, final scientific audit and human gate. Interface existence, mocked provider transport, staged manifests, or manually supplied observations cannot satisfy this gate.
