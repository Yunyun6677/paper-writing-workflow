## v0.11 audit findings

- No task requires manual `observe` when its assigned executable adapter is configured, but the compatibility CLI still permits external observation mode.
- The prior “sandbox” enforced cwd/path arguments, an environment allow-list, timeout and Windows Job Object termination. Network denial and filesystem isolation were declarations, not OS controls.
- The Codex live specialist smoke used synthetic content; it did not prove public dataset intake, repair after a real tool failure, independent numeric verification and final report in one run.
- Evidence verification recomputed citation/full-text/numeric/causal/specification facts, but did not verify a complete dataset→code→run→result→report chain.
- ScientificMemoryStore indexed artifacts and task/model relations, but lacked transformation/estimate/manuscript-claim nodes in an executable chain.
- LaTeX compilation remained staged because no TeX engine existed on the test host.
- Advanced econometric methods remained preflight-only unless separately covered by a public replication target; preflight was correctly not treated as certification.

## First v0.12 vertical slice implemented

Artifact proof: `tests/receipts/v012-public-sandbox-vertical-slice.json`.

The live run used the public `R datasets::mtcars` CSV with pinned SHA-256. A real Codex empirical specialist was required to execute an injected failing Python script. The failure produced a structured receipt and bounded stderr observation. The same specialist wrote new code, used the returned script hash, reran it under `LocalRestrictedBackend`, and produced a real OLS result. An independent reviewer session invoked deterministic analysis-chain verification. A Writing Agent created `report.tex`; a second reviewer verified the displayed coefficient against the run; the final firewall and provenance graph passed. No external `observe` command was used.

The first live attempt is intentionally retained locally: reviewer metadata omitted its explicit verification request, so it constructed a malformed request and blocked. The runtime was changed so artifact-only reviewers receive verification contracts but not producer reasoning, and ordinary tool exceptions return as repairable observations. Permission errors still fail closed into a human/security path.

## Remaining v0.12 blockers

1. Install and live-certify Docker; test read-only raw mounts, writable work/output mounts, `--network none`, CPU/memory/PID limits, secret filtering, artifact export allow-list and container termination.
2. Install a pinned TeX distribution and certify XeLaTeX/latexmk success, timeout, missing-reference and malicious-shell-escape failure cases.
3. Run process-kill/restart/reconstruct during a live Codex multi-round task, not only deterministic fixtures.
4. Certify a real OpenAI Agents SDK adapter or explicitly keep Codex CLI as the only tested backend; pin provider/model version in receipts where the host exposes it.
5. Add scholarly and dataset discovery tool E2E with rate-limit/network fault injection.
6. Expand provenance from this minimal OLS chain to transformations, merges, sample filters, tables/figures and multiple numeric claims.

## Certification statement

The new vertical slice is **tested** for one public OLS task on the current Windows host. It is not production certification of Docker security, LaTeX compilation, causal identification, arbitrary generated code, long-duration recovery or autonomous idea-to-paper research.
