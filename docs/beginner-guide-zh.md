# 零基础使用指南

这份指南写给第一次做论文、不会写代码，或者只熟悉 Excel 的使用者。你不需要先学会 Python、Stata 或 R；先把研究问题和数据说明清楚，再让 Codex 按本项目的规则工作。

## 一句话理解这个项目

你提供研究问题、文献或数据；工作流负责把任务拆成可核验步骤，保存代码、数据处理记录、模型结果、图形和失败原因，最后把可以继续交给下一环节的材料整理成标准结果包。

它目前主要有两组能力：

1. 文献工作：检索、核验真实题录、阅读全文、整理 Zotero、生成证据卡、文献地图、综述和独立创新点报告。
2. 实证工作：读取 CSV、Excel、DTA，检查变量与缺失值，运行 Python/Stata/R，生成表图，比较不同软件结果，并整理复现报告。

它不会替你决定一个研究设计天然有效，也不会为了显著而自动更换样本或模型。付费数据、个人数据和机构数据库仍需你拥有合法权限。

## 第一步：告诉 Codex 你要做什么

最小提示词可以这样写：

```text
请使用本项目的 Economics Empirical Analysis Skill 分析我提供的数据。
研究问题：贸易开放是否影响村民参加村委会选举？
观察单位：个人。
因变量：是否参加投票 vote，1=参加，0=未参加。
核心解释变量：县级出口暴露 export_exposure。
控制变量：年龄 age、性别 female、教育年限 education。
固定效应：省份和年份。
标准误：县级聚类。
请先检查数据和识别条件，再运行模型；保存所有代码、表格、图形和运行回执。
不要因为结果不显著而修改模型。无法判断的内容请列入人类交接清单。
```

你不必一次写得完美。至少说明四件事：研究问题、每一行数据代表什么、结果变量是什么、最关心的解释变量是什么。

## 第二步：把数据交给项目

### 支持的常用格式

- `.csv`：最通用，适合跨软件。
- `.xlsx`：可以使用，但必须说清工作表名称。
- `.dta`：Stata 数据，可以保留变量标签和值标签。

把文件放在项目的 `inputs/` 目录，或在对话中附上文件并说明用途。`inputs/` 默认不会上传 GitHub。

不要只说“帮我跑一下”。请同时提供一份简单数据字典：

```text
文件：survey_2025.dta
每行：一名农村居民
个人编号：person_id
村庄编号：village_id
年份：year
vote：是否参加最近一次村委会选举，1/0
meeting_count：过去一年参加村民大会次数
export_exposure：所在县出口暴露
weight：调查权重
-8、-9：问卷中的不知道和拒答，应转换为缺失值
```

如果数据含姓名、身份证、手机号、精确住址或其他敏感信息，请先脱敏。对受限数据，要在提示词中写明“restricted”，不要要求上传公共 GitHub。

## 第三步：把方法说清楚

如果你知道方法，可以直接指定：

```text
主模型使用线性概率模型；加入省份固定效应和年份固定效应；
标准误在县级聚类；使用问卷权重 weight。
稳健性检验使用 Logit，并将因变量替换为 meeting_count。
```

如果不知道方法，不要随便写“做 DID”。可以这样问：

```text
我还不能确定应该使用 OLS、Logit、DID 还是工具变量。
请先根据数据结构列出各方法需要的条件，并检查我的数据是否满足。
在我确认主模型前，只做描述统计和诊断，不要把相关性写成因果关系。
```

常见方法至少需要这些信息：

| 方法 | 你需要说明或检查什么 |
| --- | --- |
| OLS/Logit | 因变量类型、控制变量、固定效应、标准误层级 |
| DID | 处理组、处理时间、对照组、平行趋势、是否错位实施 |
| IV | 工具变量、相关性、排除限制、第一阶段和弱工具诊断 |
| RD | 阈值、运行变量、带宽、操纵检验、函数形式 |
| 面板固定效应 | 个体与时间维度、组内变化、聚类层级 |
| RCT | 随机化单位、分层方式、失访、依从性、主要结果预设 |

## 第四步：要求一个可审计的运行

推荐提示词：

```text
正式运行前，请输出并保存：
1. 原始文件哈希和数据概况；
2. 缺失值、重复主键和异常值检查；
3. 明确的样本排除规则；
4. 每个模型的 spec_id、因变量、解释变量、固定效应、权重和标准误；
5. Python/Stata/R 的版本和运行状态。

正式运行后，请输出：
1. 可重复执行的代码；
2. 系数、标准误、置信区间、p值和样本量；
3. 图形的 PNG 与 SVG；
4. 结果解释和不能支持的结论；
5. 完成、部分完成、需要复核、被阻塞四种状态之一；
6. 给下一位 agent 的机器可读结果包。
```

工作流不会覆盖已经存在的运行目录。修改设定后要新建 `run_id`，这样可以比较每一轮分析，而不是只保留最后一次结果。

## 第五步：怎样阅读结果

常见结果表字段：

| 字段 | 怎么理解 |
| --- | --- |
| `estimate` | 核心估计值；正负表示方向，大小要结合变量单位解释 |
| `std_error` | 估计的不确定性；必须和聚类/稳健方式一起看 |
| `conf_low/conf_high` | 置信区间；范围越宽表示不确定性越大 |
| `p_value` | 在模型假设成立时的数据证据，不是结论正确的概率 |
| `nobs` | 实际进入该模型的样本量；不同列变化必须解释 |
| `fixed_effects` | 模型控制了哪些不随组或时间变化的因素 |
| `clusters` | 用于相关性调整的聚类数量；太少时常规推断可能不可靠 |
| `status` | 是否真正执行并通过检查，而不是有没有生成文件 |

例如，`estimate=0.08` 的含义取决于单位：如果因变量是 0/1，可能表示约 8 个百分点；如果解释变量取了对数，解释方式又不同。不要只看星号。

## 六个可以直接复制的提示词

### 1. 数据体检

```text
请只做数据体检，不运行回归。读取我提供的文件，说明每行代表什么，检查主键、重复值、缺失值编码、变量类型、极端值、时间范围和合并风险。输出数据审计报告和建议的人类确认项，不修改原始文件。
```

### 2. 基础实证分析

```text
请使用 Economics Empirical Analysis Skill。按照我给出的主模型运行描述统计、基准回归和系数图。每个模型预先登记 spec_id，不根据显著性筛选结果。保留原始数据，所有转换写入代码和审计记录。
```

### 3. DID 检查

```text
这是一个分期实施的政策数据。请先检查处理时间、从未处理组、处理状态是否反转、样本是否平衡和处理前趋势。不要默认使用普通双向固定效应。说明候选 DID 估计量的适用条件，得到我确认后再运行主结果和事件研究图。
```

### 4. 复现一篇论文

```text
请复现这篇论文。先核验论文、数据和代码的官方来源及许可；登记论文表图与脚本的对应关系。先选择一个小而关键的结果作为验收目标，再扩展。区分数值复现、计算复现和识别有效性。无法获取或无法运行的内容必须写入交接清单。
```

### 5. 文献综述与 Zotero

```text
请使用 Social Science Literature Review Skill，围绕我的研究问题检索中英文文献。不得虚构题录；优先 DOI、出版社和作者页面。按研究项目建立 Zotero 分类，能合法获得的全文自动归档；不能获得的重要全文列出原因和我需要执行的操作。输出证据矩阵、文献地图、正式综述和单独的创新点报告。
```

### 6. 接续中断任务

```text
请读取现有运行目录和回执，从最后一个已验证检查点继续。不要删除失败运行，不要重复已经完成且哈希一致的步骤。先告诉我已完成、部分完成、被阻塞的内容，再继续执行安全且无需新授权的工作。
```

## Zotero、Stata 和 R 什么时候需要配置

- 只读本地 Zotero：保持 Zotero Desktop 运行并启用本地 API。
- 写入 Zotero 云端：需要操作系统环境变量中的 API Key；不要发到聊天或提交 Git。
- Stata：需要合法安装和 `STATA_EXE` 路径。本项目不会复制许可证文件。
- R：需要 `Rscript.exe`。无界面运行时应使用可在服务器模式工作的绘图方式。
- Python：按根目录 README 建立虚拟环境并安装 requirements。

当系统弹出权限确认时，先看清目标：读取通常风险较低；联网下载、启动本机软件、写 Zotero、提交 GitHub 会要求额外授权；删除和覆盖操作要格外谨慎。

## 什么叫真正完成

一个任务至少同时满足以下条件才应标记 `complete`：

- 输入来源和哈希明确；
- 代码实际执行且退出状态成功；
- 目标表图存在并能打开；
- 结果样本量和关键数字通过验收；
- 失败与限制没有被隐藏；
- 下游可以读取结构化结果，而不只是一段自然语言总结。

如果只跑了部分表格，就标记 `partial`；数值有差异则标记 `review-required`；登录、权限或数据缺失导致不能运行则标记 `blocked`，并告诉人类下一步应该做什么。

## 建议的新手起点

第一次使用时，不要从整篇论文开始。选择一个数据文件、一个因变量、一个核心解释变量和一张目标表。先完成数据体检与一个基准模型，再逐步增加固定效应、稳健性和图形。这样最容易发现数据定义和方法理解上的错误。
